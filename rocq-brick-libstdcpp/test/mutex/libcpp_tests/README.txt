Custom mutex runtime tests

These 17 tests are adapted from LLVM libc++ llvmorg-22.1.8:
  ca7933e47d3a3451d81e72ac174dcb5aa28b59d1

  mutex/           5 tests of MyMutex
  recursive_mutex/ 5 tests of MyRecursiveMutex
  shared_mutex/    7 tests of MySharedMutex

They check construction, prohibition of copying/assignment, exclusive locking,
recursive ownership, shared locking, and the nonblocking try-lock methods.
The .compile.pass.cpp files check type traits without creating an executable.

Run from the repository root with Python 3 and Clang:

  python3 rocq-brick-libstdcpp/test/mutex/libcpp_tests/run.py
  python3 rocq-brick-libstdcpp/test/mutex/libcpp_tests/run.py --stdlib=libc++

The default uses libstdc++. libc++ must be installed for the second command.
Both commands run the same LLVM test sources with different standard libraries.
These are custom-class tests; they do not run the standard-type baseline cases.

To use GCC's default standard library:

  python3 rocq-brick-libstdcpp/test/mutex/libcpp_tests/run.py --cxx=g++ --stdlib=default

To select a test or group, add a path substring, for example:

  --filter=recursive_mutex/lock.pass.cpp

The runner also works from other working directories. It compiles in C++17 mode
with assertions enabled, gives each compilation 60 seconds and each executable
20 seconds, and returns a nonzero status on any failure. Build outputs go into a
temporary directory that is removed after the run. There is no dependency on
LLVM lit, a full LLVM checkout, or the earlier /tmp test workspace.

UPSTREAM.json records the exact source URLs, original SHA-256 hashes, and the
adaptations. Only the tested mutex types and include directives were changed:
custom headers replace the standard mutex headers, unused includes are removed,
and required standard facilities are included directly. All upstream assertions
and the two support headers are retained. LICENSE.TXT contains the LLVM license.

These are native C++ runtime tests. test/dune-gen.sh excludes this folder from
cpp2v AST generation; run them using run.py separately from the Rocq build.

Passing these tests does not establish full standard conformance or cover all
thread schedules. In particular, they do not exercise hash collisions or the
recursive mutex's counter limit.

# brick-libcpp

Specifications of the C++ standard library in BRiCk.

## Development

To develop on these specifications, you'll need clang, the GNU C++ library (not
clang's own version), and Skylabs AI's verification toolchain.

With access to our release image, you can:
- Open this repo in a devcontainer using our Docker release image; see `.devcontainer/README.md`.

If you have access to our automation sources, you can check this out as part of
https://github.com/SkyLabsAI/workspace. After `make vendored-pull fmdeps-pull`,
you'll find a copy of this repository in `fmdeps/brick-libcpp`. Then:

- on Linux with a suitable clang + GNU C++ library toolchain, you can build this
  directly.
- on any platform, you can route AST generation through our Docker image. Use
  this route when local AST generation fails because libstdc++ headers such as
  `<cassert>` cannot be found.

Host-backed builds are the default. To enable Docker-backed AST generation,
run from the composed workspace root:

```sh
CPP2V_DOCKER_ENABLED=y dune build fmdeps/brick-libcpp
```

No local Dune file is needed. Remove any old ignored `dune` copied from
`dune.disabled`: translators are no longer shadowed on PATH.

The TU rules call the installed `cpp2v-run` helper explicitly, using a shared
configuration generated by `cpp2v-toolchain`. Dune resolves the actual host
translator, so native TU builds need no pre-existing install symlink or OPAM copy.

Inline `cpp.prog` calls remain host-only, regardless of the Docker setting. Their
host headers can differ from the image's TU headers. For fully pinned proofs
involving inline C++, run the whole build inside the pinned image/devcontainer
with `CPP2V_DOCKER_ENABLED=n`.

Docker mode uses `skylabsai/fm-releases:fm-release-nightly` by default. Set
`CPP2V_DOCKER_IMAGE` to a release tag or digest, and optionally
`CPP2V_DOCKER_USER` to a UID/GID. The cached image ID is recorded and changes
invalidate translations. Docker must be running and able to access the image;
errors do not silently fall back to host headers.

`CPP2V_DOCKER_ENABLED=if-libstdc++` selects Docker only for invocations with
`-stdlib=libstdc++`. Unsetting the variable, or setting it to `n`, restores host
execution. The execution and adapter-generation infrastructure is shipped by
the `rocq-skylabs-cpp2v` package.
